## Reflection

Today's session reminded me that software engineering is as much about learning how to think as it is about learning syntax.

One of the most valuable lessons came from when I accidentally typed an editor inlay hint directly into my source code, which resulted in a parser error that I struggled to understand at first. Rather than immediately recognizing the problem, I spent time investigating different possibilities before realizing that the gray text displayed by VS Code was simply an editor hint and not actual code. Although it was a simple mistake, it fundamentally changed how I view development tools. I now understand that IDEs provide assistance, but it is still my responsibility to understand exactly what belongs in the source code.

I also noticed that React concepts are beginning to feel more natural than they did just a few days ago. Rendering data with `.map()` initially seemed confusing because it combines JavaScript with JSX, but after implementing it myself, I started seeing how React encourages developers to think in terms of data rather than manually creating user interface elements. 

Another takeaway from today is that building software isn't always measured by how many visible features are completed. Although today's progress may seem small from the outside, the concepts I learned—component organization, TypeScript structures, React rendering, and debugging are the foundation that future features will depend on. 

I can already see my confidence improving when reading React code and interpreting compiler errors. There are still many concepts I don't fully understand yet, but I feel more comfortable approaching unfamiliar problems instead of becoming discouraged by them. My goal is not simply to finish this project, but to develop the habits and problem-solving skills of a professional software engineer.
